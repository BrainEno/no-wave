# 本机文稿密码文件：使用、核验与故障边界

Status: active

入口：写作台、作品目录、本机集合/三方工作台中的“本机加密备份”，或 `/write/vault`。
可匿名使用，不需要配置 API、邮件、对象存储或账号。完整加载应用和专用 Worker 后可离线处理
明确选入的文件；首次加载仍需要站点代码，不承诺 Service Worker 离线安装包。

## 先了解不可逆风险

- **忘记口令无法恢复。** 没有密码托管、找回入口、云端备份、自动同步或恢复任务。
- 加密只创建新副本，不删除原明文、历史下载、恢复缓存、云盘、系统备份或已泄漏的副本。
- 同源恶意脚本、浏览器扩展、被控系统和旁观者仍可能在使用时窃取口令或明文；应使用可信设备。
- 长度合格不代表口令足够强。建议使用独立的随机多词长口令，并与备份分开保管。
- 浏览器内存清零不是物理安全擦除证明，系统交换区、开发工具和密码管理器不受本工具控制。
- 结构校验、SHA-256 与 GCM 认证都不证明作者身份、媒体所有权、基线选对或服务器已保存。

## 支持什么文件

| 输入 | 既有合同 | 最大大小 |
| --- | --- | --- |
| 单篇文稿 JSON | `no-wave-writing-backup` v1 | 2 MiB |
| 文稿集合 JSON | `no-wave-writing-collection` v1，最多 20 篇 | 16 MiB |
| 三方取舍计划 JSON | `no-wave-writing-merge-plan` v1 | 64 KiB |
| 加密副本 | `no-wave-writing-vault` v1 二进制 `.nwvault` | 明文预算加规定封装开销 |

不接受任意 JSON、HTML、ZIP、嵌套密码文件或图片原始字节。扩展名只是选择器提示，
不是格式或作者凭据。不会按文件名自动选稿，不读取目录或 URL，也不寻找其他副本。

参数固定为 PBKDF2-SHA-256 / 600000 次、AES-256-GCM、随机 32-byte salt、12-byte nonce、
128-bit tag；不接受弱参数回退或文件自己指定更昂贵的计算。头长最多 1024 字节，
头与前缀的原字节都是 AAD。头不包含标题、原文件名、类型或明文摘要，但长度和算法可见。
详细格式/信任模型见 [ADR 0047](../architecture/decisions/0047-local-encrypted-writing-backups.md)。

## 手动加密与下载

1. 等待“专用本机工作线程已就绪”，明确选择一份支持的本机 JSON。
2. 只读复核类型、文稿和内容。筛选或分页只改变视图，不改变输出的成员。
3. 两次输入完全相同的 12–256 个 Unicode 字符口令，勾选不可恢复/原明文仍存在的风险确认。
   大小写、空格和 Unicode 组合形式都必须相同；不会 trim 或正规化。
4. 点击“加密并回解自检”。输入框会同步清空，Worker 完整验证后才开始原生计算。
5. 等待“新加密副本已回解自检”。这表示实际序列化的密文已经真实回解并与原字节相同，
   不是已成功落盘的证明；原明文复核会清除。
6. 另行勾选下载确认，再点击“下载新加密副本”。选择合适的本机目录，独立保管口令。
7. 建议重新选入实际下载的文件作逐字节复读，之后可重新选入该密文，重新输入口令试解。

不会改原文件、编辑区、浏览器恢复缓存或服务器。原 UTF-8 字节的 BOM、空白、字段顺序和
换行都会保留；不会重新序列化成看似相同但字节不同的 JSON。

## 手动解密、仅核验与更换口令

### 解密并预览

选择密文后，只显示未认证的文件外观和固定参数检查状态，不会根据文件名展示标题。
重新输入口令并点击“解密并预览”，认证成功后仍须通过原有载荷合同。失败不展示部分明文。
人工复核后，另行确认“将手动下载未加密的私密 JSON”，才能下载新的原始 JSON。

这会在下载目录重新产生明文副本，应留意同步目录、共用设备和磁盘备份。要恢复编辑字段，
请回既有单篇/集合/三方工具，重新选择文件、预览并确认；这里没有恢复/发布按钮。
计划只能复核语法和自附摘要，不能自动授权三份来源或恢复取舍。

### 只验证，不展开文稿

重新输入口令，点击“只验证，不展开文稿”。Worker 内完成认证和完整结构校验后清零明文字节，
只把类型、字节数、文稿/取舍数量和摘要回执发给页面，不回传正文 buffer 或文稿树，
没有明文下载。回执不是作者签名或备份历史证明。

### 更换口令，不输出明文

选择旧密文后勾选“更换口令，不输出明文”，输入原口令和两次相同、且不同于原口令的新口令，
再确认风险。工具先认证旧文件，再以新随机 salt/nonce 产生和自检**另一份**密文。

原文件仍可用原口令解密，没有被删除或撤销。新副本换口令不能修复已经泄漏的旧文件。

## 大文件原始文字复核

按需展开“查看原始 JSON（分页纯文字，含私密内容）”。每页最多 8192 个 UTF-8 字节，
边界不切断 Unicode。可前后页或输入原始字节偏移跳转，偏移从 0 开始，页末不包含在本页中。
显示分页不截短下载。部分文字组件另有按需“完整文字”展开，但仍只在当前有界字节页内。

“原始 JSON 字面检索”匹配文件字节，不是编辑区正文搜索：区分大小写、空格、JSON 转义及
Unicode 组合形式；不执行正则。检索词最多 120 个 Unicode 字符，每 64 KiB 让出检查取消，
最多显示 100 个偏移。达到上限会说明尚未穷尽，须手动继续；无匹配也只说明本次已扫描范围。

检索/定位不修改输出或下载确认。改查询会撤销旧任务；关闭原始预览会清除本次查询和结果，
来源变化或离页不能把旧偏移带到新文件。不会创建持久全文索引或保存检索词。

## 复读核对与取消

“重新选择已下载的副本”只比较这次实际选择的字节，不使用同名、修改时间或 JSON 语义相同
代替。结果区分内容变化、截断和追加，提供字节计数/偏移和摘要，但不展示差异字节内容。
这不证明未来磁盘、其他设备或所有云盘副本仍安全，也不自动读取下载目录。

换文件、改口令、清除、取消或离页会撤销旧计算/结果。原生 PBKDF2 无法强行中断，
取消之后唯一计算槽可能仍占用到真正结束；不能用取消反复启动并发 KDF，也没有自动排队重试。
页面历史返回不重读文件，不恢复已输入口令。

## 故障处理

| 状态 | 应做什么 | 不会做什么 |
| --- | --- | --- |
| 文件头/参数/完整长度无效 | 保留原稿，重新选择正确完整文件 | 不启动 KDF，不猜算法或修复头 |
| 认证失败 | 核对口令、空格/Unicode、实际文件副本 | 不区分错口令和合法外观下的篡改，不返回部分明文 |
| 载荷无效 | 用原工具核对备份格式，勿覆盖原稿 | 不把认证成功当作结构/作者凭据 |
| 原生计算仍忙 | 等真正结束后手动尝试 | 不释放假的空槽、不排队重放 |
| Worker 不可用、超时或协议错误 | 保留原稿，手动重新加载空白页面 | 不回退到主线程、不自动重启或重发口令 |
| 下载失败/复读不符 | 保留原稿和疑似副本，重新核对当前结果 | 不自动重写目录、不报告已落盘 |
| 没有安全上下文/Web Crypto | 换支持原生 Web Crypto 的可信 HTTPS 浏览器 | 不降级为明文或弱加密 |

本工具只在精确的私有工具文档授权同源 Worker，进出时整页导航是有意的 CSP 隔离，不是
路由性能故障。不要把口令、文件名或地址放到 URL。使用体验/验证记录见
[本轮审阅](../audit/writing-vault-review.md)。

合并不包含部署，#331 与 ADR 0026/0041–0043 的生产发布门禁继续独立存在。
