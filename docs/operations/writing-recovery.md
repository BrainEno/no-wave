# 写作台：可选本机恢复的使用与故障处理

这是浏览器内的文字恢复工具，**不是服务器自动保存、离线发布、跨设备同步或加密保险箱**。
产品决策和精确边界见 [ADR 0045](../architecture/decisions/0045-default-off-local-writing-recovery.md)。

## 启用、找回和备份

1. 在 `/write` 登录正确账号。默认状态为“本机文稿恢复已关闭”，编辑仍只在页面内存中。
2. 只在可信个人设备勾选未加密风险说明，点击“在此设备启用本机恢复”。同一浏览器、
   同一站点/协议/端口、当前账号的新标签会继承这次明确启用；其他设备不会。
3. 修改后约 0.6 秒尝试缓存，也可点击“立即缓存当前输入”。只有看到上次缓存时间，
   才说明应用收到了该次事务完成；“正在缓存”不是成功，更不是服务器保存。
4. 刷新/重新打开后不会自动覆盖编辑区。可以“核对账户并刷新本机列表”，选择一份稿，
   “预览本机缓存”，勾选要复制的字段，再点击“将缓存所选字段恢复到编辑区”。
5. 不同来源作品或基线修订需另外确认；正文含远程图片需明确同意之后才会由编辑器加载。
   预览不请求图片，不跟随正文链接。恢复正文可以撤销；标题/摘要/语言/类型不在正文撤销栈。
6. 恢复成功只改变当前编辑区，不切换作品、不恢复 slug/revision、不自动保存或发布。
   核对无误后按既有写作流程手动保存。重要内容仍建议下载 JSON 备份并妥善保管。

关闭且本机控制状态未变时，焦点/online 等被动检查只看 metadata，不重复联网验明账号，
也不授予缓存读取/写入权限。明确启用、主动刷新或控制状态改变时仍会重新核对真实账号。

每个编辑区/标签有独立分支。同一作品的多份缓存不会互相静默覆盖；列表按本机修订排序，
不是服务器历史版本列表，也不保证覆盖崩溃前最后一段输入。
如果预览期间继续编辑、切换目标或缓存被其他操作改变，旧预览会拒绝恢复，请重新预览。

## 上次保存结果未知时

- 在已启用缓存的页面发出文章保存请求前，会先在缓存记录“结果未知”。成功响应只结算
  对应编辑器的精确版本；保存期间继续写的内容仍未保存，不会被旧响应清空。
- 网络断开可能发生在服务器已提交之后。本机缓存没有原请求字节或幂等键，刷新之后
  **不能用缓存确认或自动重发原请求**；也不会凭文章标题猜测某一作品已创建。
- 恢复这种稿会拦截新的保存/发布。先到新标签的服务器作品目录核对已有作品、语言和
  内容，再勾选“我已核对服务器作品……”并明确解除拦截。再次新建仍可能产生重复作品。
- 原页面若仍有“确认上次保存”，它走原有的页面内精确请求协议；不属于缓存恢复。
  不要为绕开拦截而刷新或删除唯一一份未备份的稿。

## 只读核对来源服务器

每份缓存可手动“只读核对来源服务器”。它只 GET 记录的精确作品和语言，显示读取时间、
草稿/发布状态、服务器修订及字段/正文块差异。没有关联来源的新稿不请求猜测出来的作品。
不可读取可能表示删除、移动、权限或语言版本变化；不要据此推断原请求肯定失败。

- 更高修订：服务器已有后续修改，恢复旧缓存再保存可能覆盖它。
- 更低修订：先核对是否部署/备份回退，不自动替换本机基线。
- 同修订或内容等价：**仍不是原请求的成功回执**，不解除未知保存拦截。
- 结果是一次观察，不持续跟踪。网络读取后若账号、缓存版本或标签有效性变化，结果被丢弃；
  已展示结果对应的缓存被改写后也会隐藏。

读取默认最多 8 秒、2 MiB；达到差异片段预算会显示截断提示。429 仅提示等待后人工重试，
不轮询、不自动重试。该面板不把服务器正文导入编辑区、不合并、不更新缓存来源修订，
也不调用文章创建/修改/发布接口。

## 容量、删除和退出

- 最多 **20 份 / 16 MiB**（含 UTF-8 元数据）；每条还受既有 JSON 文稿结构/大小限制。
  不自动淘汰最旧的稿，不自动按时间删除。满额时先下载需要的旧稿，再明确删除。
- “下载此缓存 JSON”只下载五个可编辑字段的既有备份格式；不会附加缓存账号、来源 ID、
  修订、凭据或重试请求。作者自己输入的敏感文字/链接不会被自动脱敏。
- “删除此缓存”只删除所确认的精确本机版本，不能删除确认之后改写的新版本，不删服务器。
- “清除全部本机缓存并关闭”会原子清除本站全部缓存并使其他旧标签失效；当前输入不清空，
  服务器作品不删除。此操作可以离线尝试，不能以旧标签重新启用；先备份，再重新载入。
- 登录/注册、退出登录、撤销当前设备、重置密码的请求前后都会尝试清除。第二次清除防止
  等待响应期间新打开的标签遗留缓存；失败响应也执行。其他设备的撤销不会主动清此设备，
  此处账号失效会在下一次有界身份检查/页面生命周期检查时隐藏缓存并拒绝旧写入。
- 退出清理不删除已下载的文件，也不自动擦掉其他标签目前仍在内存的未保存编辑。
  那些旧标签会停止恢复/保存，仍可把当前输入下载后关闭。请勿把保留内存误认为缓存未清。

## 失败时怎么办

| 提示/现象                          | 实际保证                                    | 作者操作                                                               |
| ---------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------- |
| 浏览器拒绝存储、隐私策略禁用       | 没有成功缓存的承诺，当前输入不清空          | 用文稿工具下载当前输入；关闭恢复后仍可按原流程保存服务器草稿           |
| 配额不足或达到 20 份/16 MiB        | 失败写入不替换旧稿，不自动腾空间            | 下载备份并明确删除不再需要的缓存，然后手动重试                         |
| 打开被旧版本占用/超过期限/事务中止 | 不把请求 success 冒充事务 commit            | 先下载当前输入；关闭其他旧页面，手动核对后重试                         |
| 本机时钟回退/序号耗尽              | 不回写旧时间、不绕回序号、不删旧稿          | 先下载所有需要的内容；核对时钟，或明确整体清除再启用                   |
| 无法确认原登录账户                 | 缓存列表/预览隐藏，不从磁盘推断身份         | 下载当前输入；重新登录/载入正确账号后再核对                            |
| 缓存格式损坏/未知版本              | 不部分导入、不把数据交给 Lexical 才报错     | 先备份当前输入，再明确整体清除；不手改库来绕过校验                     |
| 旧标签已失效/缓存已变化            | 不恢复旧预览、不覆盖或复活其他标签的新版本  | 下载当前输入，重新载入并核对；需要时重新预览                           |
| “未能清除本机文稿缓存”             | 已尝试失效/删除，但**不承诺设备上没有旧稿** | 在浏览器设置清除此站点数据；共享设备上还应处理已下载文件并关闭所有页面 |

缓存和手动下载的 JSON 都**未加密**。同源脚本、XSS、恶意扩展、共用浏览器的人及设备备份
可能读到稿件；不同子路径不构成存储隔离。浏览器可自行回收数据，磁盘故障、断电、页面冻结
或最后一次 debounce 未完成仍可丢稿。没有请求持久存储许可，不把应用容量当成设备可用配额。
这不是对物理安全擦除、断电耐久、所有浏览器或离线身份可用性的保证。

## 开发者验证入口

```sh
node --test packages/web-ui/src/lib/writing-recovery-*.test.ts
pnpm build
pnpm exec playwright test e2e/writing-recovery.spec.ts e2e/writing-tools.spec.ts --workers=1
node docs/audit/writing-recovery-lines.ts > docs/audit/writing-recovery-lines.json
node docs/audit/verify-writing-recovery-lines.ts
```

Playwright 需要其匹配的 Chromium/系统库；默认测试使用独立可销毁 SQLite 栈，不连接生产账号。
模拟 quota/abort 和 fake IndexedDB 证明程序事务边界，不等于实测填满物理磁盘/断电。
完整检查、未跑门禁及精确源码 CI 结果见[本轮审阅记录](../audit/writing-recovery-review.md)
及其 PR；本功能不关闭真实主机或生产发布门禁。
