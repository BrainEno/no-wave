# 私信写入：账户绑定与未确认请求

## 要保护的行为

- 打开私信页时，通过私有的 `/api/authoring/session` 确认本页账户。
  身份尚未确认或响应畸形时，历史仍可阅读、草稿仍可编辑，但不能发起对话、发送或标记已读；页面提供显式重试。
- 一个发起/发送意图绑定账户、目标、规范化原文、完整 JSON 请求和一个幂等键。
  丢响应、超时、无法验证的成功响应、401、409 都不证明写入失败，也不能自动换键。
  修改原文或收件人只能先恢复原请求重试，或由读者明确放弃待确认请求。
- 另一标签页换了账户，即使新账户也在同一对话中，旧页面也不能把原消息发成新账户的消息，或更新新账户的已读水位。
- 只有有效服务器回执才结束意图：消息的 ID、conversationId、senderId、原文和 UTC 时间均须有效且匹配；
  对话回执须包含安全 ID 和原双方；标记已读必须是 `{ data: true }`。
- 待确认的发起/发送请求保护站内导航与浏览器卸载。取消离页保留原文和键；明确离页后取消本地等待、忽略迟到回执。
  成功回执会解除保护，不会让成功发起对话后的跳转被自己的导航保护拦住。
  线程的保护挂在始终存在的页面壳层；加载旧历史失败、401 或缺失分支不能把待确认发送的保护一起卸载。

## 身份边界

现代 Web 客户端在三种写请求上发送 `X-Expected-Messaging-Actor`。
值使用 `encodeURIComponent` 编为一个完整 URI component，并在代理中仅解码一次：
保留 Unicode、内部空格、逗号和字面 `%` 的 ID，不把它们误当成不同账户；
拒绝重复头字段拼接、非法编码、首尾空白、控制字符和超长 ID。
这是**限制条件**，不是认证：`packages/web-http/src/messages.ts` 校验格式，随后复用
`forwardAuthoringRequest` 的账户前置条件，用同一条已验证 bearer token 先读 `/api/v1/me` 再写入。
令牌刷新后必须重新核对；不相等返回私有的 `409 ACCOUNT_CHANGED`，不会向新账户重放写入。
头字段不会传到 REST API。客户端再读一次 session 不能代替这个代理内的同 token 检查，因为跨标签页 cookie 变化会与之竞争。

头字段对既有同源代理调用方保持可选；没有该字段的调用仍由 API 的原有认证和成员授权处理。
公共 REST 契约、幂等键的 actor scope、数据库成员约束和已读水位算法均未改变；不新增数据库迁移或授权例外。
额外成本是现代 Web 的每次写入多一次 `/me` 读取。未修改生产限流、后端重试或 outbox 语义。

## 生命周期与失败

`messaging-intent.ts` 持有不可变的页面级快照，不是跨账户全局缓存。
`messaging-transport.ts` 只调用固定的同源私有路径，使用 same-origin / no-store / redirect:error，
256 KiB 响应上限、严格 UTF-8、完整 JSON 信封和覆盖连接及 body 的 8 秒客户端期限。
失效任务的身份和 AbortSignal 共同阻止旧回执覆盖新任务；即使传输不响应取消，本地等待也能结束。
没有 focus/online 自动重发，没有消息/幂等键的 localStorage、sessionStorage 或跨标签页广播。

已读操作仍是显式 **mark-all**，不是“只读过本页”：重试可能包含请求期间新到达的消息。
它绑定本页账户，但不发明幂等键，也不自动重试；原有解释文案和服务器水位规则保留。

导航确认不是持久化保证。浏览器可能不展示卸载警告，移动系统杀进程、崩溃、强制关闭或明确选择离页都会丢失内存中的键。
再次发送前应在原账户检查历史。普通未提交的草稿不在此待确认请求保护范围内。
对话成员在创建后发生变化时，回放可能返回当前成员；若原双方已不在回执中，客户端保守保留未确认状态，读者需检查收件箱后决定是否放弃。

本切片不提供实时历史同步、跨标签页即时私有内容清屏、持久在线恢复或 push；
已加载历史的账户切换回收仍是独立工作。所有新读取和写入仍经过后端认证及成员授权。

## 验收入口

- 代理账户校验、刷新后复核、失效身份及旧调用方兼容：
  `packages/web-http/test/messaging-actor.test.ts`。
- 幂等意图、并发提交、取消、迟到响应、原文/目标/身份与回执边界：
  `packages/web-ui/src/lib/messaging-{intent,transport,leave}.test.ts`，已进入根 `pnpm test`。
- 真实 cookie、API、SQLite、丢响应后的换账户、导航/真实刷新警告、身份失败与错误发送者回执：
  `e2e/messaging-safety.spec.ts`，沿用正常 E2E 入口，无新增依赖或跳过条件。
- 原有 `e2e/messages.spec.ts` 与 `e2e/message-read.spec.ts` 继续保护丢响应、改文案、401、畸形响应、
  英文、mark-all 并发到达、成员隔离及历史分页；不删除或放宽这些验收。
- 多账户场景使一个分片需注册最多 64 个隔离账户。本地与 CI 的一次性 SQLite 测试栈统一使用 80/IP 的有限注册预算，
  为既有一次 CI 重试留余量；生产 20/IP/小时、每邮箱限流、文章创建预算及对应安全测试均不改变。
