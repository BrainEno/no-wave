# 文稿集合备份与离线核对

Status: active

本轮固定基线 `e53904a2e6d3ae8aab38d10f18542b64c52a6581`，只在 `arena/e48201b1-no-wave` 开发。历史目录与单篇写作工具不重复计数。调研开放 #284/#286/#317/#331 后，选择补齐目录只有元数据 CSV、正文只能单篇备份之间的实际缺口，不以本轮扩展关闭整个 issue；不把尚无密钥/事务 fencing 的 Notion 后台状态机冒充持久队列。

## 行为、风险与最小边界

风险 **中**：私密正文意外导出、不可信本机 JSON、晚到文件/摘要/网络响应覆盖新意图、限流和账户变化。生产边界为共享 Web UI 的 `writing-collection*` 模型/控制器/组件、既有目录详情 reader 的结构化错误窄接线、目录和写作台导航以及一个薄 React Router 页面。复用旧单篇备份的严格节点验证、应用正文适配器、文本/Markdown 导出与有界字素/块差异，不重新实现或重新计数。没有 API 写入、新产品依赖、数据库迁移、自动浏览器存稿、遥测或文件上传。

### 1. 明确选择的正文集合备份

- 只读在用目录中明确选择的 1–20 个语言版本，不因为作品有其他语言而自动读取；回收站不支持取正文，须先通过既有还原确认再选择。跨页选择沿用现有目录机制，不提高生产限流/旧全文列表的最近 100 条限制。
- 每个 GET 复用精确 id/locale/expected-author、同 bearer 账户核验及正文/修订验证。串行、有进度、可停止；账户拒绝清除私有内容，429 保留等待期限并停止，普通错误停止剩余队列，不自动重试。只在全部成功且目录账户/范围/明确选择仍匹配时准备文件。不同作品依次读取，不承诺跨请求快照；明确显示选择后发生的元数据变化。
- 只保存可由现有严格单篇备份无损表示的内容。不支持的块、格式或超限正文导致明确失败，不静默略过或改写内容。媒体仅保留经过现有校验的地址/替代文本，不请求或包含图片字节，也不证明媒体归属、链接可达或图片永久有效。
- 下载当下再次核验实际会话，并匹配当前目录/选择及准备结果；换账户、改选、挂起或离开后不能下载旧正文。集合不附加服务器文章/账户 ID、slug、发布状态、revision、令牌或重试键；文件内的组号仅在本文件有效，不是作品身份。正文中的作者自带链接可能私密，文件未加密，须妥善保管。

### 2. 版本化格式与完整性

- `no-wave-writing-collection` v1，最多 20 篇、16 MiB UTF-8 JSON；每篇内嵌一个旧 `no-wave-writing-backup` v1（仍受 2 MiB/节点/文字/深度/200 顶层块等原有限制），以及本文件局部 key/group。
- 每篇的 SHA-256 覆盖 key/group 与严格规范化后的备份；集合摘要覆盖版本、创建时间和有序条目摘要，检测条目替换、组号/顺序改动及意外损坏。SHA-256 **不是签名或身份认证**，攻击者可以一起改正文和摘要。
- 拒绝未知版本/字段、危险原型键、重复 key、同组重复语言、错误摘要、危险 URL 和非法 UTF-8。整个文件校验通过才发布，绝不把部分验证结果当可导出集合。
- 兼容已有单篇 JSON 作为单文稿输入，但明确其仅通过结构校验，原文件没有集合摘要，不能把本机转换产生的新摘要说成对原文件完整性的证明。没有 crypto.subtle 时明确拒绝集合摘要操作，不用弱散列替代。

### 3. 离线集合工作台

- `/write/collections` 是无私有 SSR 数据的本机工具壳，no-store/noindex。手动选择本机文件不需要证明服务器账户归属；不会以备份文件为登录或作品访问凭据。已加载页面可在离线时检查/下载，不上传文件、不自动请求其中链接/图片。
- 最多同时装入两份文件，每槽先按字节大小拒绝超限，再可取消地读取 ArrayBuffer、严格解码 UTF-8。另选文件、清除、卸载和 pagehide/BFCache 都使旧 FileReader/摘要完成失效；同步移除私有 DOM，返回不自动重载文件。
- 按来源/语言/类型/标题筛选和排序，只改变本机视图。显式选择允许跨筛选保留；可单篇导出旧 JSON、纯文本或有损 Markdown，也可从两份文件中明确勾选最多 20 篇重组子集。按来源文件顺序归并，保持每个来源内部的作品分组，不把两文件相同组号当同一作品，不静默去重、覆盖或删除。超过条数/字节限制全部拒绝。
- 下载前预检实际条数、组数、字节和重复内容提示；摘要计算期间输入/选择变化使准备结果作废。导出只生成本机文本下载，回收 Blob URL，不使用 HTML 或远程附件。

### 4. 明确配对的差异核对

- 文件内组号、标题或顺序均不能自动证明两份备份是同一作品。用户手动配对左右各一篇，同一条目不能重复配对，上限 20 对；未配对只说未配对，不能断言新增/删除。
- 只读计算配对字段/正文块差异，复用有界 `compareWritingDrafts`。分辨位置移动、文本及格式/链接差异，字素截断和预算不足必须显式说明。运行可取消，换文件/改配对后的旧结果无效。
- 差异绝不生成服务器写入、创建/覆盖译本或自动恢复指令。需要恢复时导出单篇旧格式，在现有写作工具中重新预览/选择；仍经过 dirty/pending、远程图片同意及后端媒体所有权验证。

## 验证与交付

先验证损坏/恶意/超限文件、摘要规范化、完整/不完整队列、账户/429/晚到 JSON、文件读取和配对/下载失效等 RED→GREEN。浏览器验证真实目录正文下载、离线读取/重组/比较、图片零请求、文件竞态、移动/axe 和旧写作工具恢复兼容。随后完整根/Web/真实 PG/四隔离浏览器、typecheck/lint/build/路由/生成契约及精确 HEAD required CI。独立行审计只纳入本基线后新增的有效生产功能，扣测试/类型/import/注释/空白/文档/CSS/配置/生成物、搬移和重复；至少 800 行。开中文 PR，fetch/review 并解决实际冲突，不自动合并或部署。

## 补齐的本机核对流程

- **跨文稿正文检索**：在已校验的来源或明确选择内检索正文，独立于清单的标题/摘要筛选；复用既有字面查找器，支持区分大小写与段落/标题/引用/列表范围，不搜索代码、链接目标或图片描述，不替换。每次最多展示 100 处，达到预算即停止后续文稿，必须披露未读或无法检查的条目；不是找到 100 条后仍全量扫描。每篇之间让出执行权，可取消；文件/范围/查询/选择变化后的旧结果不定位新文稿。命中只读定位并展示上下文，不上传查询或片段。
- **可复核计划**：另存一个不含标题/文件名/正文/账户的本机核对计划，绑定两份集合摘要、局部选择与明确配对。最多 64 KiB，严格字段/版本/摘要/范围验证；重新读取后先展示将恢复的选择/配对，只有原集合仍完全匹配且用户明确应用才改变本机清单。新文件或用户在预览后改选/改配对会使计划预览失效。不恢复正文、不自动比较或下载，也不是 signed import 的替代物。
- **无正文核对报告**：导出 JSON 或安全 CSV，记录实际已校验文件、逐篇摘要/有限统计及配对完成/未完成/受限状态。默认不包含标题/文件名，只有明确勾选才附上；永不附正文、摘要文字、链接地址、检索词/片段、账户或保存凭据。来源/配对/比较结果不匹配时拒绝生成，未核对不读作相同，局部统计不说完整。报告不是备份、不是签名/所有权证明，不承诺服务端仍有这些内容。CSV 复用既有公式/控制字符保护，不能关闭。

这些功能只扩展本机核对，不把更改后的内容送回服务器。格式/校验、读取/导出、跨文稿检索及计划/报告分别有模型/竞态与真实浏览器验收；最终有效行仍须人工排重，初步候选数不是验收结论。

### 集合级引用依赖清单

集合不带图片原文件，作者还需要知道哪些文稿依赖同一个地址。因此额外提供显式启动的集合级引用清单：复用旧单篇引用审计，以类型/规范化地址聚合所有当前来源或明确选择的使用处，并检测跨文稿“同链接文字指向不同地址”。可按图片/链接、来源、字面地址/描述、相对/外部或风险提示筛选；查看使用处只打开只读文稿，不加载地址。最多 200 个地址组 / 1000 处，达到预算停止后续文稿并列出不完整条目；取消/换来源/改选后旧清单不能定位新文稿。清单仅留在本页内存，含敏感地址但不进入无正文报告，不发任何图片/链接请求，不能据此主张媒体归属或可用性。

真实浏览器全页 axe 的配对结果场景暴露了本轮详情标题跳级，以及既有桌面品牌栏不在 landmark 内。用 `h3` 保持配对区域的标题层级，并仅用一个语义 `header` 包住原品牌栏/主导航；不改路由、可见文字、CSS 定位、键盘顺序或缓存行为，不关闭 axe 规则。该静态语义修正不计有效功能行。

最终复审补齐报告的可交接性：JSON/CSV 都须保留完成/未核对覆盖数、来源条数、单篇全部统计/问题代码计数，以及已完成配对的**无正文块位置变化**（1 起始位置、格式标记、截断标记），不能因选择 CSV 就丢掉不完整/问题信息。块位置只用于人工回查原文件，不是恢复指令；报告仍不带差异文字或地址。另保护本机下载对旧单篇便携文件名（含前导下划线）的兼容性，并拒绝读取结果与选中文件大小不符的截断/变动输入，绝不以部分字节作为完整文件。

歧义 JSON 复审用例已先失败：原生 `JSON.parse` 会吞掉同对象早先的重复字段，使含隐藏早先值的文件仍通过规范化摘要。集合/旧单篇输入/核对计划现在共用字节上限后的迭代字段预检，按解码后的字段名识别重复（包括 `\\u0076ersion` 与 `version`），跳过字符串中的括号/引号/冒号字面量，并在原生解析前拒绝超过 64 个 JSON 结构层级。该外壳预算高于既有合法正文深度，不放宽原有每篇严格深度（备份节点深度最多 5）、节点与文字限制。字段预检不代替原生 JSON 语法校验、旧备份严格校验或完整摘要校验。
