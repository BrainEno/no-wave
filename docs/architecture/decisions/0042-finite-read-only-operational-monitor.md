# ADR 0042: 运维告警使用有限只读采集与显式确认的本地事件日志

- Status: Proposed
- Date: 2026-11-12
- Implementation: implemented — 仓库内评估器、有限命令与双 provider 演练；真实主机与外部告警交付尚未验证。
- Scope: #331 的可执行告警规则切片，不代表 Phase 6、生产上线或整个 issue 完成。

## 背景

[ADR 0040](0040-notification-service-operations.md) 已区分 API、通知 worker、
存活、就绪和积压采样，但“已有指标”不等于“已有可执行告警”。HTTP `202`
也不能证明密码恢复邮件已发出；可选指标关闭、采样失败、进程替换和低流量
尤其不能被解释为健康的零。

本轮只消费现有私有 Prometheus 端点；不配置供应商账号、不部署、不更改域名、
不启动常驻监控、不运行数据库迁移、通知重投、Notion 重放或自动修复。

## 决策

1. **应用层只评估已验证事实。** `operational-alerts.ts` 管理有限规则、完整
   counter 窗口和事件状态；HTTP、文件系统与命令行留在 infrastructure。
   规则覆盖 HTTP 5xx、通知 pending 数量/年龄、死信、独立数据库健康、邮件
   投递失败，并单独报告目标不可达、服务未就绪、积压遥测不可用。
2. **一次执行，一份结果。** `ops:monitor check` 只 GET 操作者明确列出的
   `/metrics`，最多 16 个目标、4 个物理在途请求。无重定向、重试、自定义
   认证头、隐式环境目标或数据库连接。每次请求、整轮采集、响应大小、标签
   与输出等待都有上限。实际取消传输并等到 request 关闭后才释放采集槽。
3. **缺失不冒充健康。** exporter lifetime UUID 区分重启，即使重启后 counter
   更大也重建基线。倒退、异常差值、监控间隙、过期或不可用数据不能贡献
   持续阈值/恢复时间；已 firing 条件锁存。低 HTTP 流量保持 unknown；邮件
   使用失败增量，不用 `sent`/`skipped` 稀释分母。
4. **状态先于输出，确认独立于观测。** 本地私有 POSIX 日志采用独占锁、
   严格重建、配置指纹、递增 revision、临时文件 fsync → rename → 目录 fsync。
   `check` 先提交并释放锁再输出；输出失败不能丢失事件。事件以稳定 SHA-256
   ID 去重，直到 `ack --through` 确认一个实际存在的精确前缀。
   `ack` 不改变条件，也不声称服务恢复。最多保留 256 条未确认事件；满额
   拒绝新提交，不偷偷丢弃旧告警。
5. **配置变更是显式离线事务。** 默认指纹不匹配即失败；`reconfigure`
   必须同时给出旧/新配置，并先可靠交付、确认全部事件。不能移除、改名、
   换角色或重绑定有活跃条件的目标；相同来源保留锁存告警。阈值/时序
   变更重启相关 pending/recovery 连续性；窗口/采样政策变化只保留最后
   counter 基线。配置切换不是新观测，不能刷新 `lastEvaluatedAt`。
6. **旧绿灯会到期。** 离线 `status` 用持久化且严格重建的最近规则事实和时间
   判断 freshness，不抓取、不推进状态。超过 maxGap 的规则为 unknown；未交付
   事件和活跃条件仍优先 attention。`inspect` 只表示读取成功；status 的
   `observed_healthy` 也只表示最近观测，不是新的网络探针。配置切换清空旧
   verdict 缓存但不清除告警或 counter 基线，直到新 check 建立证据。
7. **操作状态不是业务数据。** monitor 不读取数据库凭据或业务 store，
   只写自己的事件日志。API metrics 的 readiness 检查会执行既有只读依赖查询；
   worker scrape 不触发查询。任何通知修复/重投另行审批。

## 不选择的方案

- 只提交 PromQL 示例：缺少本仓库可复现的缺失/重启/ack/恢复语义，无法独立演练。
- 在 API 内启动告警 timer：把监控可用性绑定被监控进程，并扩大数据库/密钥权限。
- 直接自动发送外部 webhook 或邮件：需要另行批准目的地、凭据、重试和去重策略。
- 每次配置变更删除状态：可能消失一个仍 firing 的告警或尚未交付的恢复事件。
- 抢占“过期”锁或自动重投：无法证明原进程已停；不在只读边界内。

## 后果与剩余门禁

这是进程级、单本地日志的 at-least-once 事件交付，不是 HA 告警平台。
多个 API 实例必须独立定址，不能通过负载均衡随机抓到不同进程；同一 outbox
在 API/worker 上重复可见时，消费者仍须按目标解释，不能把两份深度相加。

操作者负责私有网络、实际定时器、持久磁盘、监控自身失联探测、事件消费者和
升级/备份/回滚。JavaScript 计时器无法中断同步磁盘/native/CPU 阻塞；外部调度器
仍需硬超时。日志不支持网络文件系统或 Windows ACL；不会自动清理崩溃锁。
本地状态只有权限与结构检查，不是抗同 UID 恶意篡改的签名账本。

实现和真实进程演练见[运维规程](../../operations/operational-monitor.md)。SQLite /
PostgreSQL 测试、SMTP 连接拒绝和注入的 API 故障不是真实主机资格、实际生产
邮件投递、外部告警接收或回滚演练。#331 的其余验收继续开放，
[ADR 0026](0026-moderation-reports-and-appeals.md) 的发布门禁也不变。
