# ADR 0046: 三方文稿合并只在本机取舍，重复或顺序歧义不自动对齐

- Status: Accepted
- Date: 2026-11-12
- Implementation: Done — 仓库内的仅内存三方分析、守恒校验、手动计划与取舍/结果预览已实现；验收证据和环境缺口见[本轮审阅](../../audit/writing-merge-review.md)，不包括生产部署。
- Approval: owner 明确选择 `approve-local-three-way-full`；不是把继续开发或合并授权当作新持久化/写入授权。
- Scope: 三份明确选择的本机单篇备份、保守三方分析、逐项取舍、手动决策计划和新 JSON 下载。

## 背景、风险与最小边界

现有写作工具已有单篇备份/字段恢复、两稿展示比较和本机集合工具，但没有共同基线下的
三方取舍。展示用的 changed/moved 配对不能直接变成编辑指令：重复段落、删除与插入、
格式相同的文字或选错共同基线都可能造成丢稿。

风险为**中高**：涉及私密文件和生成文稿的完整性，但不新增服务器写入或自动浏览器存储。
边界限于 `packages/web-ui` 的 `writing-merge*` 模型、校验、控制器和组件，以及
`/write/merge` 的空壳页面与既有页面的导航。没有新 API/BFF、数据库迁移、依赖、账号权限、
后台任务、遥测或生产配置。现有恢复/未知保存请求保护保持不变。

## 决策

1. **来源由人选择，不寻找或推断。** 页面可匿名使用，SSR 是无文件的空壳，响应
   `no-store`、`noindex, nofollow`；查询参数重定向到干净路径，不把 URL 当文件地址。
   必须分别选择共同基线、当前稿、另一稿，并确认基线确是共同起点。文件时间、标题、
   摘要或同名文件都不能证明共同来源、作者、服务器身份或媒体权限。
2. **复用既有严格合同。** 每份原始文件最多 2 MiB，必须是现有单篇备份 v1。
   复用 fatal UTF-8/完整字节读取、重复（含转义）字段扫描、危险键、URL、节点、格式、
   深度、500000 文字/12000 节点/200 块及序列化上限。不接受 HTML 或把集合静默选成
   第一篇；集合需在原集合工具手动拆分。SHA-256 使用既有确定性 JSON 校验器，不引入弱摘要。
3. **精确比较，不使用“未保存语义相同”代替原文相同。** 仅忽略 JSON 对象键顺序；
   不 trim 标题/摘要，不合并文字 run，不忽略格式、链接目标、根结构或空白。
   四个元数据字段、根属性与正文区间分别决定。相同改动取一次，单侧改动给出建议；
   每项仍可人工改取共同基线、当前稿或另一稿。
4. **只对明确的唯一完整块作有界对齐。** 双侧正文分歧时，重复块或已有精确块的相对
   顺序改变都会退回整个正文冲突；不猜重复段落或移动的对应关系。如果一侧整份正文
   未变或两侧整份正文完全相同，可以整份保留已确定的候选，不需要猜测配对。
   其他情况用最多 200×200 的精确 LCS 产生基线区间，合并传递重叠的修改；同一位置
   插入、插入接触修改边界及删除/修改相遇均保守视为冲突。相邻非空区间可独立保留。
   不自动拼接两段文字，不提供未经复核的字符级合并或“同时保留两稿”捷径。
5. **两层独立守恒检查。** 发布分析前，不复用 LCS/投影算法，按来源顺序消费各候选，
   校验每一块完整出现一次、基线区间连续无遗漏、元数据和根属性完整且未变。
   输出序列化后再逐项与明确选择核对格式、正文、顺序和字段，随后保留完整备份合同
   校验。组合后超出任何原限制整份拒绝，不静默截断、丢字段、插空段落或报告部分成功。
   守恒只证明本机输入/选择的结构一致，不证明选对了基线、文意或服务器提交结果。
6. **取舍可见、可撤销、不能绕过未解决项。** 筛选和 12 项分页只是视图，隐藏的选择
   仍计入全局校验；前后冲突定位按文稿顺序循环并移动键盘焦点。显示纯文本、块数、
   格式/地址不同提示、按需精确 JSON、结果来源块数与检查提示，不渲染文件内 HTML、
   图片或可点击链接。结构路径诊断最多检查 4096 个值/40 处差异/12 层，数组长度变化
   不猜后续索引，顺序歧义不生成位置配对；达到预算明确标记不完整。显示片段截短与
   下载截短严格区分，允许显式展开完整文字；生成结果前必须解决全部冲突。结果另有
   按需的取舍影响清单：精确核对实际下载文本与预览一致，逐来源完整正文/根属性/四字段
   对照，列出未采用的已改动候选、覆盖建议、零块和冲突回基线；仍按 12 项分页、不改变
   取舍。不把“此来源候选未采用”误称为每个字都已丢失；歧义正文不生成段落身份配对。
7. **决策计划不是正文或授权。** v1 计划最多 64 KiB，只含算法、完整来源角色/摘要、
   条目编号、闭集选项、导出时间和完整性摘要，不含标题、正文、文件名、账户或请求。
   手动导出可保留未完成取舍；重新使用必须重新选择三份原文件并分析。来源摘要绑定
   完整已校验备份（含备份时间）与角色，变更任一来源即拒绝。计划也严格拒绝歧义 JSON、
   未知字段、重复/未知条目、不支持版本、坏时间或摘要。预览只展示完整替换会造成的
   选择/清空/默认变化；另行勾选确认才完整替换，不把旧选择偷偷合并进去。
   摘要不是作者签名；攻击者可重新计算摘要，人仍需核对计划内容。
8. **迟到工作不得复活。** 各来源读取、分析、结果准备、计划读取和导出分别可取消。
   来源改变同步取消所有派生结果并撤销共同基线确认；选择变更使旧结果、计划预览和
   导出失效。完整来源世代、分析对象和取舍 revision 防止改来改去的 ABA；运行状态
   发布之前建立取消 fence，迟到成功或异常不能覆盖新状态。下载分配 Blob URL 前后
   复用既有最终意图检查，清理 URL/定时器。
9. **最终只有手动文件输出。** 结果只下载新的既有单篇文稿 JSON，不写原文件、编辑区
   或服务器，不设置服务器 ID/revision/slug/发布状态，不自动导入、发布、重试或确认
   未知写入。若要继续写作，须在原工具里重新选择新文件、预览并选择字段；历史语言、
   停用类型、远程图片同意、媒体所有权和保存协议仍照原规则执行。
10. **内存不是安全擦除。** 复用 pagehide、persisted pageshow 和卸载清除；返回页面
    不重读文件。没有 localStorage/IndexedDB/Service Worker 自动缓存。不能保证浏览器
    进程内存、下载目录、开发工具、系统交换区或历史截图的物理擦除。文件未加密，
    同源 XSS、扩展、共用设备和用户自己保存/分享文件仍可能泄露内容。

## 复用与语义差异

已检索 shared-module index、`writing-session`、`writing-backup`、`writing-compare`、
`writing-document`、`writing-collection`、collection controller/浏览器工具及其调用/测试。
复用 `collectionCanonicalJson`（仅把既有私有函数导出，算法/摘要不变）、`collectionChecksum`、
`readCollectionJson`、`readCollectionFile`、`CollectionDownloadLease`、`bindCollectionPrivacy`、
备份解析/序列化、字素安全差异片段、文稿检查、导航和私有响应头。

`writingDraftKey` 有意忽略序列化默认值和两端空白，适合未保存提示，不适合无损输出。
两稿比较会启发式配对 moved/changed 行且只生成展示信息，也不适合直接用作三方编辑指令。
新增算法只承担原来没有的基线区间与闭集取舍，独立守恒校验不复制它的对齐过程。
所有模型/控制器均不导入账户、HTTP 客户端、数据库或服务器环境。

## 验证与独立门禁

高风险输入、冲突、完整性和取消/陈旧意图先建立 RED，再 GREEN；单元测试注入迟到读取、
取消和破坏区间/输出，浏览器实际选择/读取/下载文件，验证离线、恶意文字不执行、计划
不自动应用、换来源撤销下载、页面历史清理、手机布局及 axe。完整检查与本轮独立有效行
审计见[本轮审阅记录](../../audit/writing-merge-review.md)；使用说明见
[本机三方合并](../../operations/writing-merge.md)。

生产主机、跨主机、通知到人、密钥、备份/回滚与 ADR 0026/0041–0043 的发布门禁以及
[#331](https://github.com/BrainEno/no-wave/issues/331) 继续独立开放。Ready/普通 merge 授权
不等于部署、生产账号配置、自动修复、请求重放或任何破坏性服务器操作授权。
