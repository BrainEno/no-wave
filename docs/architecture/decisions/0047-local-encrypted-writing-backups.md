# ADR 0047: 文稿密码文件只在本机验证与手动另存，不托管口令或自动恢复

- Status: Accepted
- Date: 2026-11-12
- Implementation: Done — 仓库内的原生密码计算、专用 Worker、文件头预检、无损回解、只读复核与手动副本输出已实现；验证与环境缺口见[本轮审阅](../../audit/writing-vault-review.md)，不包括生产部署。
- Approval: owner 明确选择 `approve-local-encrypted-backup-full`，接受忘记口令不可恢复和同源恶意脚本/扩展在使用时可窃取内容的剩余风险。
- Scope: 明确选入的现有单篇备份、集合或三方取舍计划，加密、认证解密、仅核验、手动更换副本口令与下载后逐字节复读。

## 风险、边界与验收

风险为**高**：处理私密原文、用户口令与长期保存的文件完整性。只使用浏览器原生
Web Crypto 的 PBKDF2-SHA-256 与 AES-256-GCM，不引入第三方密码库或弱参数回退。
这是新的应用文件封装，不是独立密码学审计或标准文件格式认证。

合法文件应当回还**原始 UTF-8 字节**，包括 BOM、空白、字段顺序及换行。错口令、合法外观下
的认证篡改、截断、超限、非法载荷均不能产生可下载的部分明文。换文件、改口令、取消、
清除、离页或旧任务迟到均撤销旧意图；下载另有当前结果对象见证和独立手动确认。

不新增 API/BFF、服务器写入、编辑区写入、数据库、持久化浏览器记录、自动恢复、
同步、密码托管、请求重放或部署配置。不能删除或撤销用户已经保存的任何副本。

## 决策

1. **固定、严格、有界的封装。** `NWVAULT\n` 八字节魔数，四字节大端头长，最多
   1024 字节的 UTF-8 JSON 头，再接 ciphertext 与 16 字节 GCM tag。前缀和头的
   **原始字节**全部作 AAD，不在解密前正规化。只允许 v1、AES-256-GCM、PBKDF2、
   SHA-256、600000 次、随机 32 字节 salt、随机 12 字节 nonce、128-bit tag；未知
   字段、重复/转义重名字段、危险键、非规范 base64url、非法参数和不精确的完整长度
   都拒绝。明文最多 16 MiB；密文仅允许规定的头/前缀/tag 开销。头不含标题、原文件名、
   明文摘要、来源类型、时间或账户；仍暴露长度与算法，不能隐藏流量/长度信息。
2. **先预检，后完整读取，认证后仍严格验证。** 明确选入 Blob 后先读最多 12 字节，
   密文只再读有界头；在读完整 ciphertext 前拒绝非法参数/长度。完整读取后再次核对
   原始前缀/头，文件变化或字节数不符原子拒绝。明文必须通过现有 backup、collection
   或 merge-plan 合同；解密认证成功之后仍走相同合同，认证不替代结构校验。严格
   fatal UTF-8 解码；不能自动修复、截短或把任意 JSON/HTML/ZIP/图片当文稿。
3. **口令只短暂在内存。** 原样使用 12–256 个 Unicode 字符，拒绝控制字符、孤立代理项
   和全空白，不 trim、不正规化、不声称长度即强度。不把口令放 React state、快照、
   URL、storage、日志或网络；输入框在提交前同步清空，key 为不可导出的原生 CryptoKey，
   临时字节副本在 finally 清零。JavaScript 字符串、浏览器/系统/扩展/密码管理器和
   交换区不能保证物理擦除，清零不是安全擦除证明。
4. **一个原生计算槽、零队列、无自动重放。** 专用同源 Dedicated Worker 有版本握手、
   精确 job ID、固定 stage/error、输入/输出所有权与 transferable buffer 验证；
   未知字段或协议漂移导致终止通道，不接纳含隐藏大 buffer 的子视图。取消立即撤销
   结果资格，但不能宣称已中止原生 PBKDF2：收到真正 terminal 回应前仍占槽。10 秒
   启动预算、120 秒任务预算；失联/超时终止 Worker 并锁定 failed，只有用户重新加载
   空页面后才能重新尝试，不静默回退到主线程、自动重启或重试秘密任务。
5. **输出前检查实际封装。** 加密前完整校验原文，生成随机参数与密文后从实际序列化
   文件取回 AAD/nonce/ciphertext，用同一原生派生 key 真实回解并精确比较原字节。
   自检不等同于重新输口令的独立 KDF 或独立实现审计；另有 node:crypto 互通测试。
   加密完成清除原文预览；另行选入密文仍必须重新输入口令和复核才能下载明文。
6. **仅核验不把正文带回页面。** Worker 内认证、验证完整载荷并清零明文字节，只发
   kind、明文字节数、文稿数、取舍数、SHA-256 的闭集回执；没有明文 buffer、标题、
   draft 或正文树回传主线程。普通“解密并预览”才把已认证的原字节和只读复核模型交给
   页面；模型绝不是服务器身份或编辑器恢复指令。
7. **换口令只另存新副本。** 先认证旧密文，再以不同且重复确认的新口令、新 salt/nonce
   加密并回解自检，只产生新密文，不生成中间明文下载。原文件仍接受原口令，绝不
   自动删除或撤销；已经泄漏的旧副本不会因换新副本口令而变安全。
8. **只读复核有界且不改变文件成员。** 复用现有文稿纯文字展示，不装载文件内图片/链接，
   不渲染 HTML。标题/摘要/语言筛选、文稿导航和计划 12 项分页只改变视图。原始 JSON
   每页最多 8192 个 UTF-8 字节，不切断 Unicode；偏移跳转和前后页不生成全文 DOM 副本。
   原始文字检索使用线性 KMP 精确字节匹配，不使用正则或正文语义正规化；每 64 KiB
   让出并检查取消，最多返回 100 个不含原文的偏移，达到上限明确说明未穷尽，后续须
   手动继续。查询改变、关闭预览或来源变化撤销旧搜索，不创建持久索引。
9. **下载不是落盘回执。** 当前结果需单独勾选确认，分配 Blob URL 前后都检查活见证；
   下载交接后清理临时副本与 URL，清除/离页撤销未交付的旧结果。可重新手动选择真实
   下载文件，分块逐字节比较，区分内容变化、截断、追加，错误不展示差异字节。
   名称、修改时间、JSON 语义相同、哈希相同都不替代这次实际文件选择/完整比较。
10. **CSP 是 Document 能力，不能靠 SPA“换策略”。** 仅精确 `/write/vault`、200 且
    no-store 的生产 HTML 允许 `worker-src 'self'`，不开放 blob/data/external Worker；
    其余文档仍为 `'none'`。脚本内容哈希、事件属性禁止和 framing 基线不变。共享导航
    seam 对进出该路径使用完整文档导航，查询参数重定向到干净路径；页面私有、noindex，
    SSR 无文件/口令，不从 URL 自动读文件。pagehide、persisted pageshow 与卸载清除
    本页，返回不重读。真实历史遍历与合成 persisted 生命周期分别验证，不把合成事件
    称为浏览器已经实际收纳 BFCache 的证明。

## 复用与语义差异

已检索 shared-module index、`writing-backup`、`writing-document`、`writing-collection`、
`writing-merge-plan`、`writing-collection-browser`、`writing-collection-search`、
`writing-replace` 及其调用和测试。复用原结构/URL/节点/大小合同、重复键扫描、SHA-256、
纯文字文稿组件、下载 lease、生命周期清除、私有 HTTP 头和导航 seam。

既有 collection checksum 是规范 JSON 的内部校验，不代表原 UTF-8 文件字节，故另有
原字节摘要和复读。既有 collection/replacement search 面向编辑区节点与正文语义锚点，
不能给出包含 BOM/JSON 转义的原始文件字节偏移，故新增有界原字节搜索，不复制编辑器
替换或修改规则。独立 plan parser 只证明语法/自附摘要，仍须在三方工作台用原来源角色、
摘要、条目和当前分析重新授权；原预览检查不因 parser 抽出而削弱。

## 验证和剩余风险

原生密码、参数/认证/载荷、取消/ABA、rotation、文件头预检、原字节分页/搜索、协议形状
有行为 RED→GREEN；模拟桥不冒充真实 Worker，浏览器另跑真实原生计算与下载。
完整证据、严格行数审计及尚不可本机运行的门禁见[审阅记录](../../audit/writing-vault-review.md)。

忘记口令不可恢复；同源恶意脚本、浏览器扩展、被控系统、旁观者、下载目录/云盘和原有
明文副本仍可泄露内容。不能把加密验证、Ready 或 merge 当作生产部署授权。
[#331](https://github.com/BrainEno/no-wave/issues/331) 与 ADR 0026/0041–0043 门禁继续独立开放。
