# ADR 0013: Generated article slugs and automatic summaries

- Status: Accepted
- Date: 2026-10-29

## Context

Saving an article from the Lexical editor failed for most real documents, and the
two remaining write fields were the author's problem to solve by hand:

1. **The slug was hand-authored.** The editor required a value matching
   `^[a-z0-9]+(?:-[a-z0-9]+)*$`, which is impossible to type sensibly for a
   Chinese title. Authors either invented an ASCII title or got stuck.
2. **The summary was hand-authored or empty.** An empty summary meant an empty
   description on the archive, article and social surfaces.
3. **Saving silently failed** with one opaque message. Two causes were found by
   probing the adapter against a live API:
   - Lexical >= 0.52 emits `textFormat` / `textStyle` on element nodes whenever a
     block inherits a text format. The adapter's key allow-list predates those
     keys, so every such block failed the conversion.
   - Lexical always keeps a trailing (often empty) paragraph, and authors leave
     blank lines and trailing spaces behind. The block contract requires
     non-empty, trimmed text, so a single blank block rejected the whole save.

The public article address is `/articles/<slug>` and the stored contract is
ASCII-only, so the slug scheme has to be a transliteration decision, not a
formatting one.

## Decision

1. **The slug is generated by the API, never authored.** The Web editor no longer
   sends one on creation. `POST /api/v1/articles` without a `slug` derives it from
   the title; a client-supplied slug is still honoured (trimmed) and keeps its
   `409 ArticleSlugConflictError` if it is taken — the API never silently renames
   an address the client chose. `PUT` still requires the slug of the article it
   updates.
2. **Chinese titles are transliterated to tone-less pinyin**, not dropped.
   Dropping non-ASCII (what a naive filter does) turns most titles on this site
   into an empty string, and percent-encoded Han in a path is hostile to sharing
   and to Baidu, which reads pinyin in URLs. Titles are segmented with
   `Intl.Segmenter` first, so syllables group per word:
   `无浪文学的第一篇文章` → `wu-lang-wenxue-de-di-yipian-wenzhang`. Latin words are
   kept and accent-folded (`Café` → `cafe`). The result is capped at 60 characters
   on a word boundary; a title with nothing transliterable falls back to
   `article-<8 hex chars of sha256(title)>`, which is stable across retries.
   `pinyin-pro` (MIT, no runtime dependencies, server-side only) provides the
   readings; it is imported by the API alone and never reaches the browser bundle.
3. **Uniqueness is owned by the database.** `articles.slug` already has a unique
   index. A generated slug that collides is re-suffixed (`-2`, `-3`, … up to 20,
   then a hash suffix) by retrying the insert inside the existing transaction
   boundary, rather than by adding a pre-check port that both persistence adapters
   would have to implement.
4. **A blank summary is generated from the body.** Paragraphs, headings, quotes
   and list items contribute text; code and images do not. Text is split with
   `Intl.Segmenter` sentence granularity and whole sentences are kept while they
   fit in 110 characters. Only when a single sentence is longer than the budget is
   it cut, at a word boundary (word granularity), so Latin words stay whole and
   ICU's dictionary keeps Chinese words whole. Two invariants hold: a summary
   never ends on punctuation that cannot end a sentence, and `…` is only appended
   when text was actually cut — never directly after another punctuation mark.
   A summary the author wrote is preserved verbatim.
5. **Blank blocks no longer fail a save.** The adapter drops blocks whose text is
   empty after trimming (and empty list items, and empty code blocks), trims edge
   whitespace from the remaining runs so the trimmed-text contract holds, and
   fails with a content-specific message when nothing is left. Element-level
   `textFormat` / `textStyle` are accepted and ignored: the article contract stores
   marks per inline run, and the child text nodes already carry the format.

## Consequences and operational limits

- A slug is immutable once published by convention, same as before: renaming an
  article does not rename its address, because `PUT` sends the stored slug.
- Changing the pinyin provider, the ICU data or the 60-character cap changes the
  slug a future article gets. Existing slugs are untouched.
- `pinyin-pro` is a ~0.9 MB unpacked server dependency on the API only; the Web
  bundle and the browser do not carry it.
- Summaries are generated from the first ~110 characters of prose. A work whose
  opening is a code block, an image or a very long first sentence gets a cut
  excerpt; authors can always write their own.
- `Intl.Segmenter` is required for sentence and word granularity. Node and current
  browsers have it; without it the code degrades to a hard cut, which still
  respects the trailing-punctuation and ellipsis invariants.

## Validation contract

- Unit tests pin the slug contract (ASCII, stored pattern, length cap, stability,
  distinctness, hashed fallback, unique-suffix ladder) without asserting one exact
  transliteration, because ICU word segmentation may shift between runtimes.
- Unit tests pin the summary invariants: no ellipsis after punctuation, no half
  Latin words, complete sentences kept whole, code and images skipped, blank input
  yields a blank summary.
- Adapter tests cover element-level `textFormat`/`textStyle`, dropped blank blocks,
  trimmed edge whitespace, and the empty-content error.
- Transport tests cover the write body: slug optional on create, required on
  update, generated summary, and the content-specific error message.
- End-to-end (local API, SQLite): create without a slug returns `201` with a
  pinyin slug; a second article with the same title gets `-2`; an explicit summary
  survives; an all-blank document returns `400` naming empty content.
